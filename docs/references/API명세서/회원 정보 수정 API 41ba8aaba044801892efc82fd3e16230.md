# 회원 정보 수정 API

API Path: /my/profile
HTTP 메서드: PATCH
도메인: 마이 화면
상태: 시작 전

### 회원 정보 수정 API

> 로그인한 사용자의 닉네임 또는 이메일을 변경합니다. 전달된 필드만 수정하고, 전달하지 않은 필드는 기존 값을 유지합니다.
> 

### Authentication

필수(JWT)

## Request Header

| 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `Authorization` | String | O | `Bearer {accessToken}` |

## Request Body

| 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `nickname` | String | X | 변경할 닉네임 |
| `email` | String | X | 변경할 이메일 주소 |

두 필드 중 최소 하나는 전달해야 합니다.

```json
{
  "nickname": "전문셀러",
  "email": "seller@example.com"
}
```

## Response Form Example

### Success

```json
{
  "status": 200,
  "message": "회원 정보가 수정되었습니다.",
  "data": {
    "userId": 1024,
    "nickname": "전문셀러",
    "email": "seller@example.com",
    "updatedAt": "2026-11-17T15:30:00+09:00"
  }
}
```

## Response Data

| 이름 | 타입 | 설명 |
| --- | --- | --- |
| `userId` | Number | 회원 고유 ID |
| `nickname` | String | 수정 후 닉네임 |
| `email` | String | 수정 후 이메일 주소 |
| `updatedAt` | DateTime | 마지막 회원 정보 수정 시각 |

닉네임은 앞뒤 공백을 제거하고 빈 문자열을 허용하지 않습니다. 이메일은 올바른 이메일 주소 형식인지 검증합니다.

요청에 포함되지 않은 필드는 기존 값을 유지합니다. 요청 본문에 수정 가능한 필드가 하나도 없으면 요청을 거부합니다.

이메일 변경 시 이후 발송되는 서비스 알림 및 문의 답변에 변경된 이메일을 사용합니다.

`loginId`와 `password`는 이 API에서 변경하지 않습니다. 비밀번호는 별도의 비밀번호 변경 API를 사용합니다.

본인의 회원 정보만 수정할 수 있으며, 수정 요청에 `userId`를 전달받지 않고 JWT로 사용자를 식별합니다.
