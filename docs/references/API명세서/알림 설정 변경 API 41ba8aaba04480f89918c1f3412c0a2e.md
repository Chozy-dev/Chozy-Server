# 알림 설정 변경 API

API Path: /my/notification-settings
HTTP 메서드: PATCH
도메인: 마이 화면
상태: 시작 전

### 알림 설정 변경 API

> 사용자의 알림 수신 방식, 알림 종류별 활성화 여부 및 변동 기준을 수정합니다. 전달한 설정만 변경하고 나머지 설정은 유지합니다.
> 

### Authentication

필수(JWT)

## Request Header

| 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `Authorization` | String | O | `Bearer {accessToken}` |

## Request Body

| 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `emailEnabled` | Boolean | X | 이메일 알림 활성화 여부 |
| `eventTypes` | Object | X | 알림 종류별 활성화 설정 |
| `eventTypes.supplyPriceEnabled` | Boolean | X | 공급가 변동 알림 활성화 여부 |
| `eventTypes.scoreChangeEnabled` | Boolean | X | 점수 변화 알림 활성화 여부 |
| `eventTypes.stockOutEnabled` | Boolean | X | 품절 알림 활성화 여부 |
| `eventTypes.restockEnabled` | Boolean | X | 재입고 알림 활성화 여부 |
| `eventTypes.searchVolumeEnabled` | Boolean | X | 검색량 급상승 알림 활성화 여부 |
| `thresholds` | Object | X | 변동 알림 기준값 |
| `thresholds.supplyPriceChangePercent` | Number | X | 공급가 변동률 기준(%). 1~100 `[설계 제안]` |
| `thresholds.scoreChangePoints` | Number | X | 점수 변동폭 기준. `5`, `10`, `15` |
| `thresholds.searchVolumeIncreasePercent` | Number | X | 검색량 증가율 기준. `30`, `50`, `100` |

최소 하나의 설정값을 전달해야 합니다. 중첩 객체에서도 전달하지 않은 필드는 기존 값을 유지합니다.

```json
{
  "emailEnabled": false,
  "eventTypes": {
    "supplyPriceEnabled": true,
    "scoreChangeEnabled": true,
    "stockOutEnabled": true,
    "restockEnabled": true,
    "searchVolumeEnabled": false
  },
  "thresholds": {
    "supplyPriceChangePercent": 10,
    "scoreChangePoints": 10,
    "searchVolumeIncreasePercent": 50
  }
}
```

## Response Form Example

```json
{
  "status": 200,
  "message": "알림 설정이 변경되었습니다.",
  "data": {

    "emailEnabled": false,
    "pushStatus": "COMING_SOON",
    "eventTypes": {
      "supplyPriceEnabled": true,
      "scoreChangeEnabled": true,
      "stockOutEnabled": true,
      "restockEnabled": true,
      "searchVolumeEnabled": false

  }
}
```

## Response Data

| 이름 | 타입 | 설명 |
| --- | --- | --- |
| `inAppEnabled` | Boolean | 앱 안 알림 활성화 여부. 항상 true |
| `emailEnabled` | Boolean | 변경 후 이메일 알림 활성화 여부 |
| `pushStatus` | String | 푸시 알림 제공 상태 (`COMING_SOON`) |
| `eventTypes` | Object | 변경 후 알림 종류별 설정 |
| `eventTypes.supplyPriceEnabled` | Boolean | 공급가 변동 알림 |
| `eventTypes.scoreChangeEnabled` | Boolean | 점수 변화 알림 |
| `eventTypes.stockOutEnabled` | Boolean | 품절 알림 |
| `eventTypes.restockEnabled` | Boolean | 재입고 알림 |
| `eventTypes.searchVolumeEnabled` | Boolean | 검색량 급상승 알림 |
| `thresholds` | Object | 변경 후 알림 기준 |
| `thresholds.supplyPriceChangePercent` | Number | 공급가 변동률 기준(%) |
| `thresholds.scoreChangePoints` | Number | 점수 변동폭 기준(점) |
| `thresholds.searchVolumeIncreasePercent` | Number | 검색량 증가율 기준(%) |
| `updatedAt` | DateTime | 설정 변경 시각 |

알림 설정은 사용자별로 저장하며, 수정 성공 시 전체 최신 설정값을 반환합니다.

공급가 변동률은 기획서상 기본값 10%만 확정되어 있습니다. 설정 가능한 범위 `1~100`은 `[설계 제안]`이며 서버에서 유효성을 검증합니다.

점수 변동폭과 검색량 증가율은 기획서에서 지정한 선택지만 허용합니다. 잘못된 값은 요청을 거부합니다.

`inAppEnabled`는 MVP에서 항상 true이므로 변경 요청에서 받지 않습니다. 푸시 알림 역시 아직 지원하지 않으므로 `pushStatus`를 변경할 수 없습니다.

이메일 알림을 꺼도 앱 안 알림은 유지됩니다. 특정 알림 종류를 비활성화하면 해당 종류의 개인 변동 알림은 앱 안 알림과 이메일 알림에서 모두 생성하지 않습니다.

시스템 알림과 서비스 공지는 이 API의 종류별 설정 대상이 아닙니다. 이메일 알림의 활성화 여부와 광고성 정보 수신 동의는 별개입니다.

품절·재입고 알림은 사용자가 종류별로 켜고 끌 수 있지만 별도의 수치 기준을 설정하지 않습니다.

설정 변경은 이후 발생하는 알림부터 적용하며, 이미 생성된 알림 목록과 기존 읽음 상태에는 영향을 주지 않습니다.

검색량 급상승 알림은 관심상품에 등록된 상품의 분석 키워드(`wishlist_items.keyword`)만 추적합니다. `INTERESTED`(관심중)와 `SELLING`(판매중) 상태를 모두 포함하며, 스크리닝 기록의 키워드나 전체 키워드는 추적하지 않습니다.
