# Chozy Server 현재 상태

Chozy Server는 위탁 셀러의 상품 소싱 검증을 위한 REST API다. 현재 작업 범위는 Spring 서버이며 운영 연동은 후속이다.

## 구현 상태

| 범위 | 상태 |
| --- | --- |
| 공통 기반 | 공통 성공·오류 응답, 보안·CORS, OpenAPI, DB 없는 기본 프로필과 격리 PostgreSQL 개발 프로필 |
| 계정 | 개발용 일반 가입, 로그인, JWT 재발급·로그아웃, 회원 정보·비밀번호·광고 수신 동의 변경, 회원탈퇴·토큰 무효화 |
| 마이페이지와 홈 | 대시보드와 무료 월간 분석 사용량 조회. 관심상품과 회원 스크리닝 사용량을 각 기능의 저장 데이터에 연결 |
| 홈 공급 조건 우수 상품 | 설정 시 Collector의 `read_supply_home`으로 소싱처별 최신 완료 발행본을 조회한다. 실제 DB에서 발행본 조회 검증은 대기 중이다. |
| 홈 쿠팡 베스트 | 설정 시 Collector의 최신 완료 발행본에서 카테고리, 상품 순위와 전일 변동을 JDBC로 읽는다. 격리 DB에서 API 검증을 마쳤고 운영 연결은 대기 중이다. |
| 홈 네이버 시즌·쿠팡 비교 | 설정 시 Collector의 최신 완료 네이버 발행본을 JDBC로 읽고 동일 기준일의 완료 쿠팡 상품과 비교한다. 격리 DB에서 API 검증을 마쳤고 운영 연결은 대기 중이다. |
| 키워드 스크리닝 | 요청·최근 기록, 쇼핑인사이트 분야, 저장한 키워드의 쇼핑 반응과 점수 재계산 계약 구현. 네이버 데이터 제공자는 미연동 |
| 직접 입력 정밀분석 | 작업·리포트·사용량 경계와 opt-in 시장 분석 엔진 구현. 진행 조회에서 키워드 조회(4)와 시장 데이터 조회(5)를 제공한다. 쿠팡 시장가·네이버 검색광고·데이터랩으로 스냅샷을 생성한다. 쿠팡 검색 호출 오류 시 예상 판매가를 받는 계산 대기 리포트를 저장한다. 엔진 설정 전 503이며 실제 외부 API·공동 예산 DB 검증은 대기 |
| 상품 URL 정밀분석 | 공개 URL 판별, 도매꾹→도매매 전환, 옵션 검증, 회원 요청·진행 계약 구현. 실제 소싱처 조회 제공자와 분석 엔진은 미연동이며 필요한 요청은 503을 반환 |
| 리포트 | 본인 리포트 상세·최근 기록·점수 의견, 쿠팡 대분류 조회, 추가 입력 저장·재계산 구현. 실제 키워드·옵션 갱신 제공자는 미연동 |
| 관심상품과 알림 | 직접 입력 리포트에서 관심상품 등록·목록·상세·상태 변경·판매 결과 기록·삭제 구현. 알림 설정 조회·변경, 저장된 알림 목록과 개별·전체 읽음 처리 구현 |
| PostgreSQL | 기존 격리 개발 DB에 V1~V12 적용. V12는 작업 진행 단계 저장 컬럼을 추가한다. 운영 DB 적용은 대기다. |

패키지별 책임과 통합 경계는 [BACKEND](BACKEND.md#패키지와-의존-방향)를 참고한다.

## 최신 검증

2026-11-26 리포트 점수 모듈 분리 후 `mvnw.cmd -B verify` 기본 테스트 91개와 패키징이 통과했다. 점수 결측·판매 제한에 의한 상한과 CPC 등급 경계를 확인했다. 이번 리팩터링의 Docker 기반 `db-test`는 실행 대기다.

같은 날 앞선 검증에서 Collector DDL을 적용한 격리 PostgreSQL 16.16과 컬럼 단위 읽기 전용 로그인으로 홈 베스트·시즌·비교 API를 확인했다. 완료·미완료 발행본, 기본·명시 선택, 전일 비교 결측, 동일 기준일의 중복 제거와 조회 권한 오류를 검증했다.

대체 응답으로 공급 추천의 빈 발행본·연결 실패와 쿠팡 503/429 후 계산 대기 리포트·공동 차단을 검증했다. 별도 격리 DB에서 공동 함수나 실행 권한이 없을 때 예약 전에 실패하는 것을 확인했다.

2026-11-24 실행한 격리 PostgreSQL 16 통합 테스트 78개에서 V12의 신규 설치와 기존 V6 리포트가 있는 DB의 업그레이드, 직접 입력의 진행 단계 저장·역행 방지·시간 초과, 리포트 저장·사용량 경계를 확인했다. 회원탈퇴·토큰 무효화, 리포트 추가 입력, OpenAPI도 회귀 검증했다.

기존 격리 개발 DB는 백업 후 V11에서 V12로 올렸다. Flyway 이력과 `processing_step` 컬럼, 회원·작업·리포트·사용량의 적용 전후 행 수를 확인했다. 당시 JAR로 OpenAPI 경로와 공개 카테고리 HTTP 200, 인증 없이 호출한 진행·상세·사용량 HTTP 401을 확인했다.

## 개발 순서

1. 마지막 확인 때 공동 예산 정책은 0건이었다. Spring 전용 로그인으로 예약 함수 접근을 확인했으며, 쿠팡 `default`·네이버 `ad`/`trend` 계정 매핑과 한도를 등록한 뒤 검증 인스턴스에서 직접 입력 한 건을 확인한다. [실데이터 검증 절차](../README.md#직접-입력-정밀분석-실데이터-검증)
2. 홈 조회의 운영 발행본 권한과 실제 조회를 확인한다. 정밀분석의 키워드별 쿠팡 비교·Wing 추천·세부 요율, 스크리닝, URL 소싱처, 관심상품 추적과 외부 알림을 실제 데이터에 연결한다.
3. 공개 전 본인인증·DI·소셜 계정, 탈퇴 후 데이터 보존·비식별화·재가입, 운영 DB 역할·배포를 확정하고 검증한다.
