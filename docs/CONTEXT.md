# Chozy Server 현재 상태

Chozy Server는 위탁 셀러의 상품 소싱 검증을 위한 REST API다. 현재 작업 범위는 Spring 서버이며 운영 연동은 후속이다.

## 구현 상태

| 범위 | 상태 |
| --- | --- |
| 공통 기반 | 공통 성공·오류 응답, 보안·CORS, OpenAPI, DB 없는 기본 프로필과 격리 PostgreSQL 개발 프로필 |
| 계정 | 개발용 일반 가입, 로그인, JWT 재발급·로그아웃, 회원 정보·비밀번호·광고 수신 동의 변경, 회원탈퇴·토큰 무효화 |
| 마이페이지와 홈 | 대시보드와 무료 월간 분석 사용량 조회. 관심상품과 회원 스크리닝 사용량을 각 기능의 저장 데이터에 연결 |
| 홈 공급 조건 우수 상품 | 공개 목록 조회 계약 구현. 소싱처별 최신 완료 발행본의 응답을 검증했다. 실제 Collector 조회 제공자는 미연동이며 H001/503을 반환한다. |
| 홈 쿠팡 베스트 | 공개 조회 계약 구현. 최신 완료 발행본에서 카테고리를 선택하고 전일 순위 변동을 반환한다. 실제 Collector 조회 제공자는 미연동이며 H002/503을 반환한다. |
| 홈 네이버 시즌·쿠팡 비교 | 공개 조회 계약 구현. 시즌 테마별 상위 키워드와 같은 기준일의 발행본 비교 결과를 제공한다. 실제 조회 제공자는 미연동이며 H003/503을 반환한다. |
| 키워드 스크리닝 | 요청·최근 기록, 쇼핑인사이트 분야, 저장한 키워드의 쇼핑 반응과 점수 재계산 계약 구현. 네이버 데이터 제공자는 미연동 |
| 직접 입력 정밀분석 | 요청·예약·진행 조회, 작업 처리·만료, 리포트 저장·사용량 기록 경계 구현. 시장 데이터와 산식 엔진은 미연동이며 현재 요청은 503을 반환 |
| 상품 URL 정밀분석 | 공개 URL 판별, 도매꾹→도매매 전환, 옵션 검증, 회원 요청·진행 계약 구현. 실제 소싱처 조회 제공자와 분석 엔진은 미연동이며 필요한 요청은 503을 반환 |
| 리포트 | 본인 리포트 상세·최근 기록·점수 의견, 쿠팡 대분류 조회, 추가 입력 저장·재계산 구현. 실제 키워드·옵션 갱신 제공자는 미연동 |
| 관심상품과 알림 | 직접 입력 리포트에서 관심상품 등록·목록·상세·상태 변경·판매 결과 기록·삭제 구현. 알림 설정 조회·변경, 저장된 알림 목록과 개별·전체 읽음 처리 구현 |
| PostgreSQL | V1~V5는 기존 개발 DB 적용 이력 있음. V6~V11의 기존 개발 DB와 운영 DB 적용은 별도다. V11은 회원 탈퇴 시각을 추가한다. |

## 구조

- Java 21/Spring Boot 모듈형 모놀리스다. `common`에 공통 웹·보안 설정을 두고 `auth`, `member`, `home`, `usage`, `screening`, `analysis`, `report`, `favorite`, `notification`에서 각 기능을 담당한다.
- JWT로 회원을 식별하고 업무 데이터의 소유권을 확인한다. PostgreSQL의 `chozy` 스키마에서 Flyway로 버전을 관리한다. 자체 데이터는 별도 저장소와 트랜잭션 경계를 사용한다.
- `analysis`는 두 입력 방식의 작업 접수·예약·진행·리포트 저장을 처리한다. `UrlProductCatalog`는 상품·옵션 조회, `ManualAnalysisEngine`과 `UrlAnalysisEngine`은 각각 리포트 계산 경계다. 완료된 리포트는 `usage` 원장과 함께 커밋한다.
- `screening`은 검색과 쇼핑 지표를 가공하고 점수·4분면을 계산한다. `ScreeningDataProvider`가 검색광고와 데이터랩 조회 경계를 담당한다.
- `home`의 `RecommendedProductReader`, `CoupangBestReader`, `NaverSeasonReader`는 각각 완료 추천·쿠팡 베스트·네이버 시즌과 비교 발행본의 조회 경계를 담당한다.
- `report`는 저장된 분석·리포트 조회, 점수 의견, 추가 입력 재계산과 저장을 담당한다.
- `favorite`은 등록 시점 리포트 데이터와 판매 결과를 저장한다. `notification`은 회원별 설정과 읽음 상태를 관리한다. 공급처 상품 추적, 시장가 갱신, 외부 이벤트 알림 생성·전송은 연동 단계에 남아 있다.

## 최신 검증

Maven 기본 테스트 78개가 통과했다. 공개 홈 조회의 입력·발행본 선택·빈 응답·제공자 부재와 네이버·쿠팡 비교의 기준일 일치를 확인했다. 회원탈퇴는 비밀번호 확인·계정 비활성화·토큰 폐기 호출과 비활성 계정의 로그인·인증 차단을 오프라인에서 확인했다.

격리 PostgreSQL 16의 리포트·OpenAPI 통합 테스트 18개는 리포트 추가 입력 구현 때 통과했다. 입력 유효성·소유권, CPC 경계와 초기화, 스냅샷 경합 감지, 재조회 및 무료 횟수 비차감을 검증했고 키워드·옵션 갱신은 제공자 픽스처로 확인했다. Docker 엔진 미가동으로 V11 적용, 실DB 회원탈퇴·토큰 무효화 및 최신 DB 통합 회귀는 검증 대기다.

## 개발 순서

**다음 작업은 직접 입력 정밀분석에 실제 시장 데이터와 분석 산식을 연결하는 것이다.** 홈 조회와 회원탈퇴를 포함한 원본 명세 39개의 서버 경로가 구현됐다. 외부 데이터 연동과 운영 검증은 아래 순서로 진행한다.

| 순서 | 구현 범위 | 완료 기준 |
| --- | --- | --- |
| 3. 실제 데이터와 계산 연결 | 직접 입력에 시장가·수수료·검색광고·데이터랩 및 분석 산식을 연결한다. 이어 스크리닝, URL 소싱처, 홈 발행 조회, 관심상품 추적과 외부 이벤트 알림에 실제 데이터를 연결한다. Collector 구현·운영 전환 일정은 별도다. | 실제 데이터로 리포트와 진행 단계를 확인하고 호출 한도, 캐시, 필드 누락, 실패·재시도, 데이터랩 소진 시 차감 면제를 검증한다. 홈 조회는 발행 완료본 단위로 확인한다. |
| 공개 전 계정과 운영 검증 | 회원탈퇴 정책의 DB 회귀, 삭제·비식별화 및 재가입 정책, 휴대폰 본인인증·DI, 소셜 계정, 운영 DB 역할과 배포를 점검한다. | 탈퇴 정책과 운영 데이터·계정, 외부 연동의 실제 적용 상태를 확인한다. |

각 API는 기획서와 원본 명세의 인증·입력·성공 응답부터 확인하고, 실제 구현과 오류·소유권 테스트를 함께 갱신한다. 명세에 빠진 경합·오류 계약은 선택한 동작과 근거를 BACKEND에 남긴다. 실제 데이터 경로가 준비되기 전에는 외부 응답을 테스트에서만 대체하고, 실행 환경에서 처리할 수 없는 요청은 현재 정밀분석의 503 계약처럼 명시적으로 응답한다.

실행·환경 설정은 [README](../README.md), API 계약과 트랜잭션 규칙은 [BACKEND](BACKEND.md), 기획 원문은 [references](references/)에서 관리한다. 변경 작업마다 이 문서의 현재 상태·문제·다음 작업을 갱신한다.
